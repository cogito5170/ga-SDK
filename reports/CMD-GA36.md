## 요약 (한국어)

- **GA CLI `ga ask`**: 질문을 정해진 동작 8개(help, status, next, run, report, usage, doctor, stop) 중 하나로 바꿉니다. 고르는 것은 키워드 규칙이고 모델은 쓰지 않습니다. 맞는 것이 없으면 가까운 셋을 보여 주고 추측하지 않습니다. 토큰을 쓰는 동작(run, `--model`, `--solve`)과 메일 동작(report)은 실행할 것, agy 턴 수, 예상 토큰을 먼저 보여 주고 y/N을 묻습니다. `--yes`는 메일에만 통합니다. 하루 agy 턴 한도는 10입니다.
- **`ga ask --solve`와 UI의 Solve 칸**: 같은 `solve.run` 경로입니다. ga의 도구 표만 쓰고, 턴 한도는 8입니다. 턴마다 supervise 로그에서 입력·출력 토큰, 초, 도구 단계를 한 줄씩 보여 줍니다. 끝에는 답, 합계(턴 줄들의 합), 고정 오버헤드 비중을 보여 주고 `~/.ga-ask/ledger.jsonl`에 한 줄을 남깁니다.
- **`ga bridge`**: baseline의 agy bridge를 흡수했습니다. 도구는 ga 안에 있고(`ga.bridge.tools`), 기존 `~/agy-bridge.json`이 그대로 동작합니다. 503 MODEL_CAPACITY_EXHAUSTED는 한 번 다시 해 보고, 그래도 안 되면 `capacity` blocker로 보고합니다(할당량과 구분).
- **GA UI `ga ui`**: 127.0.0.1에서만 열리고, 일회용 토큰을 쓰며 Host와 Origin을 검사합니다. 동작은 POST와 토큰이 있어야 하고, CSP가 엄격하며 실행 기록은 SSE로 보여 줍니다.
- **기다리기**: 코드가 로그 파일을 읽어서 합니다(`ga/runlog.py`). 기다리는 동안 모델 호출은 없습니다(테스트에서 fake agy 호출 수로 확인).
- **확인하지 못한 것**: 실제 agy에서 `--mode plan`이 도구를 끄는 데 충분한지, 그리고 json usage 형태는 Mac에서 실제로 돌려 봐야 정해집니다. 실제 모델 실행은 0회입니다.
